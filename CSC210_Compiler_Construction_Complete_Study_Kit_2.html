📚 In-Depth Topic Coverage

1️⃣ SYMBOL TABLES

Definition

A data structure maintained by compilers to store information about entities (variables, functions, classes, etc.) that appear in the source code. Format: <symbol_name, type, attribute>

Purposes

  • Store names of all entities in structured form
  • Verify if variable has been declared
  • Implement type checking
  • Determine scope of names (scope resolution)

Implementation Methods

  • Linear (sorted/unsorted) list: Easy to code, suitable for small tables only
  • Binary Search Tree: Better for medium-sized tables
  • Hash Table: Most common - source symbol is key, value is symbol info

Core Operations

  • insert(symbol, attributes): Add symbol to table (used by analysis phase)
  • lookup(symbol): Search for symbol - returns 0 if not found, else returns attributes

Scope Management

Compiler maintains TWO types: Global symbol table (accessible by all procedures) and Scope symbol tables (created for each scope). These are arranged in hierarchical structure.

Search Algorithm: (1) Search current scope first, (2) If not found, search parent scope, (3) Continue until found or global table is searched.

2️⃣ BASIC BLOCKS & CONTROL FLOW GRAPHS

Basic Block Definition

Sequence of consecutive statements with only ONE entry point and ONE exit point. Once first instruction executes, ALL instructions execute sequentially until end. NO branching in middle.

Characteristics

  • Only one entry point (first instruction)
  • Only one exit point (last instruction)
  • No branch instructions except possibly at end
  • If ANY instruction executed, ALL are executed sequentially

Finding Leaders (Basic Block Boundaries)

Rules for identifying leaders (first instructions of blocks):

  • First instruction in intermediate code
  • Any instruction that is TARGET of conditional/unconditional jump
  • Any instruction immediately FOLLOWING a conditional/unconditional jump

Algorithm to Partition Instructions into Basic Blocks

  1. Identify all leaders using the 3 rules above
  2. For each leader, its block = leader + all instructions up to (but NOT including) next leader
  3. Each instruction belongs to exactly ONE block

Control Flow Graph (CFG)

Directed graph showing all possible paths through program. Each basic block = node. Edges show control transfer. Reveals program structure for optimization.

3️⃣ CODE OPTIMIZATION

Optimization Criteria

Best transformations = most benefit for least effort. Must:

  • Preserve program semantics (meaning must not change)
  • Measurably speed up or reduce code
  • Worth the effort (cost-benefit analysis)

Local Optimizations (within one basic block)

  • Common Sub-expression Elimination: If b*c appears twice, compute once and reuse
  • Constant Folding: Evaluate constant expressions at compile time
  • Variable Propagation: Replace variable with its value if constant
  • Dead Code Elimination: Remove assignments to variables never used
  • Copy Propagation: Replace x with y if x:=y and neither changed

Loop Optimizations

  • Loop-Invariant Code Motion: Move expressions that don't change outside loop
  • Induction Variables: Recognize & optimize loop counters
  • Strength Reduction: Replace expensive ops (multiply) with cheaper (add/shift)
  • Loop Unrolling: Reduce loop overhead by executing multiple iterations

Global Optimizations (across basic blocks)

Requires data-flow analysis to track how values flow through program. Identifies available expressions (can be reused) and dead code across blocks.
