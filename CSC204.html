Unit 1 — Introduction to Big Data Analytics

▼

What is Big Data?

A massive, complex dataset rapidly generated and transmitted from sources like social media, e-commerce, financial markets, and streaming services.

The 5 V's

VMeaningExample
VolumeEnormous amount of dataMillions of WhatsApp messages/day
VelocitySpeed of generation/processingTwitter processes millions of tweets/sec
VarietyDifferent types/formatsEmails, videos, images
VeracityAccuracy/trustworthinessSpam or misinformation on social media
ValueUsefulness for decisionsPersonalized ads, patient data analysis

Memory trick: "5 V's" = Very Vast Varied data — Verify it's Valuable.

Types of Big Data

  • Structured — fixed format, relational DB (bank transactions, student records)
  • Semi-structured — some structure, not tabular (XML, emails, logs)
  • Unstructured — no predefined format (images, videos, audio, social posts)

Sources of Big Data

  • Social Media (Facebook, Twitter/X, Instagram, YouTube, TikTok)
  • IoT Devices (thermostats, GPS, health monitors, sensors)
  • Transactional Data (ATM, POS, online purchases)
  • Web/Clickstream Data (page views, search queries, downloads)

Traditional Data vs Big Data

Traditional DataBig Data
Smaller volumeMassive & complex
Structured onlyStructured + semi + unstructured
Relational DBNoSQL / distributed file systems
StaticDynamic, constantly changing
Historical insightReal-time + predictive insight

Types of Big Data Analytics

  • Descriptive — "What happened?" (Sales dropped 20%)
  • Diagnostic — "Why did it happen?" (Price increase caused drop)
  • Predictive — "What's likely to happen?" (Forecasting churn)
  • Prescriptive — "What should we do?" (Reduce prices)

Memory trick: D-D-P-P in order of maturity: Descriptive → Diagnostic → Predictive → Prescriptive.

Applications (by sector)

  • Retail/E-commerce — personalized recs, dynamic pricing
  • Healthcare — disease prediction, resource management
  • Media — content recommendation, sentiment analysis
  • Banking — fraud detection, credit risk assessment
  • Government — crime pattern analysis, public health surveillance

Big Data Analytics Lifecycle (6 stages)

  1. Discovery — define the problem/objective
  2. Data Collection — gather from multiple sources
  3. Data Preparation — clean, remove duplicates, fix errors
  4. Data Analysis & Model Planning — queries, stats, ML
  5. Data Visualization — charts, dashboards (Power BI, Tableau)
  6. Data Presentation — reports, recommendations, decisions

Memory trick: "Dis Cool Dudes Analyze Visually, Presenting" (Discovery, Collection, Cleaning(Prep), Analysis, Visualization, Presentation)

Benefits

  • Better decision making
  • Enhanced customer experience
  • Innovation/product development
  • Real-time analytics

Challenges

  • Data quality
  • Data integration
  • Data security
  • Scalability/storage bottlenecks
  • Talent gap

Unit 2 — Big Data Ecosystem

▼

The Big Data Ecosystem = collection of technologies, frameworks, and processes to collect, store, process, analyze, and visualize big data.

Purpose

  • Efficient data management
  • High-speed processing (Spark, Hadoop)
  • Advanced analytics (ML, data mining)
  • Visualization (Tableau, Power BI, Kibana)

Core Components (6 layers)

  1. Data Sources — social media, IoT, apps, websites
  2. Data Storage — distributed file systems, NoSQL DBs
  3. Processing Frameworks — batch, stream, distributed
  4. Data Analytics Layer — insight extraction
  5. Visualization Tools — Tableau, Power BI
  6. Security Layer — access control, encryption, backup

Distributed File Systems

Key characteristics: Scalability, Fault Tolerance, High Availability, Data Replication

HDFS (Hadoop Distributed File System): splits data into blocks (128MB/256MB), distributes across DataNodes; a NameNode tracks metadata & block locations; replication (2–3 copies) gives fault tolerance.

NoSQL Databases (4 types)

TypeExamplesUse Case
Document-OrientedMongoDB, CouchDBUser profiles, IoT data
Column-OrientedCassandra, HBaseTime-series, event logging
Key-Value StoreRedis, DynamoDBCaching, sessions
Graph DBNeo4j, ArangoDBSocial networks, fraud detection

Memory trick: "Doc Col Key Graph" — Document, Column, Key-Value, Graph.

Processing Frameworks (3 types)

TypeTraitTools
BatchScheduled, delayed resultsHadoop, Spark
StreamReal-time, low latencyKafka, Flink, Storm
DistributedParallel across machinesHadoop, Spark, MapReduce

Security Layer

Access control, encryption, data privacy, backup & recovery.

Unit 3 — Big Data in Cybersecurity

▼

Cybersecurity Goals (CIA Triad)

  • Confidentiality — only authorized access
  • Integrity — accuracy & completeness of data
  • Availability — accessible when needed

Common Cyber-Attacks

  • Malware — viruses, worms, trojans, ransomware
  • Phishing — impersonating a legitimate source
  • DDoS — overwhelms system with traffic
  • Insider Threats — current/former employees with access
  • IoT-based attacks — target smart cameras, wearables, sensors

Big Data in Cybersecurity — Definition

Large-scale data collection, storage & advanced analytics to detect, prevent, and respond to cyber threats in real time — analyzing network logs, user behavior, firewall events, threat intel feeds to find IOCs (Indicators of Compromise).

Data Sources for Cybersecurity (4 categories)

CategoryIncludes
Network DataFirewall logs, proxy logs, traffic logs
Endpoint DataProcess data, file activity, user activity, network connections
IAM DataAuthentication logs, authorization logs, directory service logs
Physical Security DataAlarm/sensor data, surveillance footage

Applications of Big Data in Cybersecurity (8)

  • Threat detection & identification
  • Fraud detection & prevention
  • Intrusion Detection Systems (IDS)
  • Network traffic analysis
  • User & Entity Behavior Analytics (UEBA)
  • Predictive cybersecurity
  • Vulnerability assessment & risk management
  • Digital forensics & incident investigation

How Big Data Works in Cybersecurity (6 stages)

  1. Data Collection (Acquisition Layer)
  2. Data Storage (HDFS, cloud, data lakes)
  3. Data Processing (clean, standardize, filter)
  4. Data Analysis (ML + statistical analysis)
  5. Alert Generation
  6. Incident Response (block IP, isolate systems, disable accounts)

Benefits

  • Faster threat detection
  • Improved fraud prevention
  • Enhanced monitoring
  • Better decision making
  • Predictive security analysis
  • Better incident response

Challenges

  • False positives
  • Model drift
  • Complexity (many tools to manage)
  • Data quality problems
  • High storage cost
  • Scalability/performance
  • Fast-changing threats

Unit 4 — Big Data for Network Forensics

▼

Network Forensics = branch of digital forensics that monitors, captures, records, and analyzes network traffic to investigate cybercrimes. Answers: What / When / How / Who / What systems affected.

Objectives (5)

  • Identify cyberattacks
  • Gather digital evidence
  • Trace attackers
  • Understand attack methods
  • Improve future security measures

Network-Based Evidence Sources

Switches, Routers, DHCP Servers, Authentication Servers, IDS/IPS, Firewalls, Application Servers.

Types of Network Data

TypeDetails
Flow DataSource/dest IP, duration, packet count
Log DataFirewall, IDS/IPS, DNS, web proxy, DHCP, auth logs
Packet DataHTTP requests, emails, video streams (most detail, huge volume)

Network Forensic Process (6 phases)

  1. Identification — recognize an incident occurred
  2. Collection — gather packets, records, logs
  3. Preservation — protect evidence integrity (write protection, backups)
  4. Analysis — examine, correlate, reconstruct events, trace source
  5. Documentation — record every step
  6. Presentation — clear, accurate, evidence-based report

Memory trick: "I Can Preserve Analysis, Document, Present" — ICPADP.

How Big Data Applies to the Process

  • Ingest massive logs in real time — Kafka, Flume
  • Parse/normalize/filter — Logstash, Apache NiFi (raw log → structured fields → consistent format → only relevant records)
  • Distributed queries across data lakes — Hive, Spark SQL (parallel search across many computers)
  • ML-based threat classification
  • Correlate events from multiple sources (VPN + DNS + endpoint)
  • Visualize timelines — Kibana, Grafana

Parsing = extracting meaningful fields from raw data. Normalization = converting different formats into one consistent structure. Filtering = keeping only relevant records.

Benefits

  • Faster investigation
  • Real-time monitoring
  • Better threat detection
  • Enhanced attack attribution
  • Better decision making
  • Scalable storage/processing

Challenges

  • Storage costs
  • Data complexity
  • High processing requirements
  • Need for skilled investigators

Unit 5 — Design Considerations for Big Data Software Tools

▼

Big Data software tools (e.g. Hadoop, Spark) collect, store, process, analyze, and visualize massive data. Poor design → data loss, security breaches, slow performance, crashes, high costs.

7 Key Design Considerations

ConsiderationMeaning
1. ScalabilityHandle growing data/users without losing performance (Horizontal = more servers; Vertical = more CPU/RAM/storage on one server)
2. ReliabilityOperate correctly & consistently over time
3. PerformanceSpeed/efficiency — response time, throughput, processing speed
4. Fault ToleranceKeep working when components fail — replication, backups, redundant servers
5. SecurityConfidentiality, Integrity, Availability — authentication, authorization, monitoring
6. UsabilityEasy to learn/use — friendly UI, clear navigation
7. MaintainabilityEasy to update/repair/improve over its lifecycle

Memory trick: "Some Really Practical Features Save Usability & Maintenance" → Scalability, Reliability, Performance, Fault Tolerance, Security, Usability, Maintainability.
